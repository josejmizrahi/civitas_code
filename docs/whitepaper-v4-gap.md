# Whitepaper v4 — Comparación PDF vs web

## Lo que el PDF v4 (EN) tiene y la web ya cubre bien
- Problema de opacidad (governance opacity)
- Tesis: decisiones + dinero + identidad conectados
- Tres primitivas core (Identity, Treasury, Governance) con descripción alineada
- Ciclo cerrado (3 conexiones: Gobernanza→Tesorería, Tesorería→Identidad, Identidad→Gobernanza)
- Contrato social configurable / motor de reglas
- Arquitectura (RLS, multi-tenant, escalabilidad)
- Activación progresiva (import → operar → automatizar → conectar → federar)
- Mercado objetivo (condominios, cooperativas, religiosas, etc.)
- Visión a futuro

## Lo que falta en la web (a implementar)
1. **Cinco primitivas** — En v4 son cinco: Identity, Treasury, Governance, **Census**, **Federation**. La web solo muestra tres.
2. **Alianza Fintech (IFPE)** — CLABE, SPEI, cobro automático, desembolsos por gobernanza, modos de tesorería (Import, Connector, Fintech Rail, Hybrid). La web no describe el modelo de partnership ni el rail financiero.
3. **Modelo de ingresos** — SaaS + comisión por transacción (0,5%) + productos financieros futuros.
4. **Estrategia de despliegue en 5 fases** — Validar (1 edificio) → Integrar (10, rail) → Escalar (100 comunidades) → Federar (1.000) → Network State (10.000+).
5. **Mercado ampliado** — PDF: 930K condominios, 60K cooperativas, 50K NGOs, 28K religiosas, 25K clubs, 15K sindicatos, 15K cámaras, 200K asociaciones escolares, 100K vecinales. Web: números distintos (50K religiosas, 15K industriales).
6. **Competencia** — Tabla comparativa (admin software, DAO, civic tech vs Civitas).
7. **Riesgos y mitigaciones** — IFPE, abuso de auto-ejecución, regulación, etc.
8. **Roadmap técnico** — Fases 1–7 (Core MVP → Pilot → Financial Rail → Integrated Primitives → Multi-vertical → Federation+Census → Scale).
9. **Seguridad y privacidad** — RLS, aislamiento, cool-down, segregación de fondos.
10. **Conclusión** — “Civitas is infrastructure that makes network states possible” + referencias (Srinivasan, Ley Fintech).
